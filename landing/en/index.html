03 — SERVER SETUP

Setup on
the server.

Two honest paths. Most people need Path A only. Path B unlocks FlyStream and gives WuPlay / Stremio a local manifest — pick where the little Node server lives.

Path A · ~60 seconds · Recommended

Zero-server — use the GitHub manifest

7Movies + Movy run as plugins inside your player (QuickJS on the TV). There is nothing to host. Paste one URL into Nuvio and you're done — it syncs to the TV instantly.

  1. On phone or computer, open nuvioapp.space/account → sign in → Plugins → Add plugin.
  2. Paste the manifest URL below → Save. Check the TV: the providers appear — that's your confirmation.
  3. On the TV, enable Settings → Content & Discovery → Plugins → “Enable plugin providers globally” (sideloaded Nuvio build required — Play Store builds disable plugins).
https://raw.githubusercontent.com/phuanh004/direct-streams-providers/refs/heads/main/manifest.json
Path B · ~10 minutes · For FlyStream + self-host

Companion server — run server.js

A zero-dependency Node server on port 7070. It serves the manifest, injects its own address into FlyStream, and holds the challenge cookies FlyStream needs. Run it on a Pi, an always-on PC, or in the cloud.

  • Node.js 18+ (tested to Node 26)
  • Same Wi-Fi as the TV for LAN options — use the .local hostname, never a raw IP
  • Keep it running while you watch FlyStream titles
git clone https://github.com/phuanh004/direct-streams-providers.git
cd direct-streams-providers
npm install  # esbuild
npm run build
npm run serve  # → :7070
  1. Run the server on the Pi / PC with the commands in Path B. Leave that terminal (or a pm2 / systemd service) running.
  2. Find its .local name — e.g. raspberrypi.local or your PC's hostname. A .local name survives DHCP changes; a raw IP silently breaks later.
  3. Give players this manifest (below). Every device on the same Wi-Fi can use the same URL.
http://<companion-host>.local:7070/manifest.json
  1. Deploy the included worker.js with wrangler.toml from the repo — same code, Cloudflare's edge instead of your Pi.
  2. Use the Workers URL it prints as your manifest host, in the form https://<your-worker>.<account>.workers.dev/manifest.json.
  3. Best when the TV isn't on your home LAN, or you don't want a box running 24/7.
  1. Import the repo into Vercel — the same server.js deploys as the add-on server.
  2. Use your deployment URL + /manifest.json in Nuvio / WuPlay / Stremio.
  3. Re-deploy after updating the repo to pick up new provider builds.

Run the offline suite first (no network, no hammering live APIs), then one live check:

npm run test:offline  # stubbed units + router + flystream + movy
npm test             # live — keep occasional

Healthy output looks like: Oppenheimer (872585) → 1 stream · Breaking Bad S01E01 (1396) → 4 streams, 1080p–360p, subs = 8.

Don't skip this: FlyStream returns no streams from the plain GitHub manifest. It only works through Path B, because the companion injects its own address when it serves providers/flystream.js.
04 — CLIENT SETUP

Setup on
each player.

Same providers, three front doors. Do the server step once — then add the manifest to each player you actually use.

  1. Install the sideloaded Nuvio build on the TV (Play Store builds have plugins disabled by policy).
  2. Add the plugin from your phone — Path A above. It syncs to the TV immediately; no typing URLs with a remote.
  3. Or on the TV itself: Settings → Content & Discovery → Plugins → Manage from phone (QR), or paste into “URL or short code” → + Add. Then switch ON “Enable plugin providers globally.”
  1. Start the companion server (Path B) — npm run serve on :7070.
  2. Open WuPlay config: on TV go to Settings → Configuration and scan the QR to open config.wuplay.app — WuPlay keeps add-ons in its cloud profile, so this one setup follows you to every WuPlay device.
  3. Add the manifest in the .local form below.
http://<your-host>.local:7070/manifest.json
  1. Start the companion server (Path B) on :7070.
  2. Paste the manifest into Stremio's search bar, or open the stremio:// form.
  3. Check: the add-on appears in your add-ons list and titles gain extra stream rows.

Use the same .local hostname form as everywhere else on this page — Stremio accepts it, and it survives DHCP changes unlike a raw IP.

http://<your-host>.local:7070/manifest.json

05 — DAILY USE

Every day,
every screen.

Setup is once. This is the part you live in. Tap a device to see its job — the system is designed so each screen does what it's best at.

A normal day with it

ANYTIME — PHONE

Find it on the bus

Browse on your phone, open the title, check which provider has it and at what quality. Nothing to download — you're just scouting.

EVENING — TV

Play it on the big screen

Open the same title in Nuvio on TV. Pick Movy 2160p for the film, 7Movies 1080p if the Wi-Fi is busy. Subtitles are already in the list — pick yours and play.

IN THE FILM — ANY SCREEN

Choose like a regular

Higher isn't always better: 1080p MP4 starts fastest and seeks cleanly; 4K HLS shines on a wired / strong-Wi-Fi TV. If one provider stalls, back out and take the same title from the other — that's why there are three.

TRAVEL — TABLET / LAPTOP

Take it with you

Path A travels free — the GitHub manifest works anywhere. Path B LAN manifests only work at home; away from home use Path A, or your Cloudflare / Vercel deployment.

If a stream won't play

  1. 428 / blocked? You're on an old build — re-add the latest manifest so streams carry the okhttp headers.
  2. 429 / empty list? Wait a minute. The providers back off and cache failures briefly on purpose — mashing retry makes it slower, not faster.
  3. FlyStream empty? Your companion server isn't running, or you used a raw IP that changed. Start server.js, use the .local URL.
  4. Nothing at all? In Nuvio, check “Enable plugin providers globally” is ON and you're on the sideloaded build.

Why it stays smooth

Built for 1.5–2 GB TV boxes: a hard 9-second deadline per provider, O(1) LRU/FIFO caches, shared in-flight lookups, and single-pass HLS parsing. 7Movies retries with exponential backoff + jitter and honours Retry-After; Movy tries one attempt per server — Miami and Boise first, sliding window of 3 — and caches a 429 for 30s instead of hammering the API.

Weekly habit: pull the repo, npm run build, restart the companion — two minutes, and every device picks it up from the same manifest.

06 — ANSWERS

Before
you ask.

Do I need an account or API key?

No provider account or API key for the streams — just the manifest URL for 7Movies and Movy. The recommended Nuvio install uses your Nuvio sign-in at nuvioapp.space only to sync the plugin to your TV (or use the in-app TV method). FlyStream additionally needs your companion server running.

Do I need the server at all?

Only for FlyStream, WuPlay, and Stremio add-on mode. For Nuvio with 7Movies + Movy, Path A (GitHub manifest) needs no server — the scrapers run on the TV itself.
